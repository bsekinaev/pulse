# ПУЛЬС — адаптация новых сотрудников

> Тестовое задание для ТГТ. Демонстрационный B2B-сервис: сигнал новичка → зарегистрированная проблема → действие руководителя → результат.

**Статус:** MVP, исключительно вымышленные сотрудники. Продукт не интегрирован с реальным Битрикс24.

## Возможности

- Защищённая административная панель и карточки сотрудников.
- Персональная ссылка на анкету для третьего дня адаптации.
- Три коротких вопроса; отрицательные ответы создают проблемы соответствующих категорий.
- Устранение проблемы с сохранением комментария и времени.
- Отображение количества сотрудников, открытых и закрытых проблем, отсутствующих ответов.
- Защита от повторной отправки, подпись анкеты, CSRF на административных формах.

## Быстрый запуск для разработки

Требуется Python 3.12 или новее.

```bash
git clone https://github.com/bsekinaev/pulse.git
cd pulse
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
python -m uvicorn app.main:app --reload
```

На Windows вместо `source .venv/bin/activate` используйте `.venv\Scripts\Activate.ps1`. Публичный доступ к dev-серверу запрещён.

Локальный адрес: http://127.0.0.1:8000

Локальные учётные данные **только для разработки на loopback**: `admin` / `local-dev-admin`. В production приложение требует настоящие секреты из `.env` и не запускается с короткими значениями.

Синтетические сотрудники создаются автоматически при первом запуске. Алексей М. (первый сотрудник) ещё не отправил анкету — на нём удобно показать основной сценарий. Заходите в панель и выбирайте его карточку.

## Автоматические тесты

```bash
python -m pytest -q
```

Проверяются создание и повторная отправка анкеты, категории проблем, закрытие обращения, контроль доступа, CSRF, невалидные токены и идемпотентность заполнения БД. Результат CI смотрите в GitHub Actions — не считайте тесты пройденными только по наличию исходников.

## Production Docker

```bash
cp .env.example .env
# Заполните APP_SECRET_KEY (32+ случайных символов), ADMIN_PASSWORD (12+ символов).
# Пример генерации: python -c "import secrets; print(secrets.token_urlsafe(48))"
docker compose up -d --build
docker compose ps
curl -fsS http://127.0.0.1:18120/health
```

В Windows PowerShell вместо `cp` используйте `Copy-Item`.

Порт `18120` доступен только с localhost хоста. Для публичного HTTPS требуется отдельная DNS-запись и маршрутизация через существующий Caddy. **Перед изменением Caddy проверьте, работает ли он на хосте или в Docker-контейнере.** Порядок безопасного внедрения описан в [deploy/README.md](deploy/README.md).

Docker использует отдельный volume `pulse_data` для SQLite и непривилегированного пользователя. Секреты не помещаются в репозиторий. Не выполняйте `docker compose down -v` на стенде с нужными данными.

## Основной сценарий демонстрации

1. Откройте `/login` и войдите под административной учётной записью.
2. Перейдите в карточку Алексея М. и откройте ссылку на анкету.
3. Выберите отрицательный ответ «Нет, нужна помощь» на вопрос об оборудовании; укажите отсутствие ТСД.
4. Отправьте анкету и убедитесь, что показано подтверждение.
5. Вернитесь на `/dashboard`: появилась новая проблема, показатели изменились.
6. Откройте проблему, напишите, что сделали, и зафиксируйте решение.
7. Проверьте статус «Решено» и увеличившийся счётчик закрытых проблем.

## Архитектура

- `app/main.py` — HTML-маршруты, сессия администратора, ссылки на анкеты, CSRF.
- `app/models.py` — Employee, CheckIn, Issue.
- `app/services/onboarding.py` — атомарное сохранение анкеты, категории, закрытие.
- `scripts/seed_demo.py` — воспроизводимые данные восьми вымышленных сотрудников.
- `app/templates/`, `app/static/` — интерфейс.
- `tests/` — интеграционные и негативные тесты.

## Ограничения

- Используется один чек-ин на третьем дне; автоматические напоминания не реализованы.
- Роли HR и руководителя объединены в одну демо-административную роль.
- Нет реальной синхронизации с Битрикс24, почтой или мессенджерами.
- Не рассчитываются прогнозы увольнения и не заявляется подтверждённое сокращение текучести.
- Нет промышленного аудита операций, управления пользователями, rate limiting и резервного копирования по расписанию.
- Личный URL анкеты действует 7 суток и должен передаваться только нужному человеку.
- SQLite + 1 worker подходят для прототипа, но не означают готовность к промышленной нагрузке.
- Внешний вид — корпоративно ориентированная интерпретация, не официальный брендбук ТГТ.

## Безопасность

Не используйте реальные личные данные, не публикуйте `.env`, не подключайте настоящий Битрикс24 без согласования. Учётные данные администратора демостенда передавайте проверяющему отдельно.
