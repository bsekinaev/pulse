# PULSE-017: резервное копирование SQLite (подготовка v0.2.0)

Резервная копия выполняется средствами **SQLite Online Backup API**,
поэтому исходную базу не нужно останавливать для согласованного снимка.
Функция `backup_sqlite()` проверяет `integrity_check`, внешние ключи
и наличие основных таблиц; готовый файл имеет права `0600` на POSIX (Linux/macOS).
На Windows `os.chmod` не задаёт NTFS ACL — безопасность зависит от
прав доступа родительского каталога. Резервные копии на Windows следует
хранить только в приватном каталоге профиля пользователя и отдельно
проверять ACL средствами Windows.
Существующий файл резервной копии не перезаписывается.

## Изолированное локальное использование

```bash
python -m scripts.backup_sqlite \
  --source ./pulse.sqlite3 \
  --destination ./backups/pulse-20261111.sqlite3
```

Каталог назначения создаётся заранее, а для надёжности должен быть
**вне Docker volume приложения**. В git не добавлять сами копии БД.

## Совместимость с Windows

`fsync` вызывается на временном файле, открытом в режиме `r+b`.
В отличие от открытия только для чтения (`rb`), этот режим совместим
с `os.fsync` на Windows. Изменения не затрагивают данные БД:
SQLite завершает создание снимка до открытия этого дескриптора.
Регрессионный тест проверяет режим открытия файла перед публикацией.
