# PULSE-017 — проверенное восстановление SQLite

Восстановление выполняется **только в новый файл**. Существующая база
никогда не перезаписывается. Перед публикацией результата проверяются
целостность SQLite, внешние ключи и наличие таблиц ПУЛЬС.

## Изолированная проверка

```bash
python -m scripts.backup_sqlite \
  --source ./pulse.sqlite3 \
  --destination ./backups/pulse-smoke.sqlite3

python -m scripts.restore_sqlite \
  --backup ./backups/pulse-smoke.sqlite3 \
  --destination ./backups/pulse-restored-smoke.sqlite3
```

Каталог `./backups` нужно создать заранее. Ни backup, ни восстановленную
базу нельзя коммитить в Git или открывать через HTTP. Для VPS использовать
отдельный защищённый каталог за пределами рабочего Docker volume.

**Запрещено:** вызывать восстановление поверх `/var/lib/pulse/pulse.sqlite3`
или выполнять это упражнение внутри работающего production-контейнера.

В CI проверяется полный путь: синтетические данные → backup → restore →
сравнение метрик → независимость восстановленной копии от архива.

Следующие работы: сравнение схемы с реальным дампом после безопасного
получения копии, Alembic upgrade и отдельный релизный rollback.
