# PULSE-010 — безопасность входа и административных сессий

Реализация для экспериментальной ветки v0.2.0:

- Пять неуспешных попыток за 15 минут блокируют дальнейший вход с источника.
- При блокировке сервер возвращает HTTP 429 и `Retry-After`.
- Счётчик хранится в SQLite; адрес источника не сохраняется в открытом виде.
- При успешном входе неуспешные попытки этого источника очищаются.
- Административные сессии хранятся сервером в виде SHA-256 от случайного токена.
- Выход из системы отзывает сессию даже при повторном предъявлении cookie.
- Срок действия административной сессии — 4 часа.
- Добавлены CSP, `Referrer-Policy: no-referrer`, `X-Frame-Options`,
  `X-Content-Type-Options` и `Cache-Control: no-store` на личных страницах.
- Удалён inline JavaScript обработчик в карточке сотрудника.
- Добавлена миграция Alembic `20261111_0002`; на VPS пока не применять.

## Доверие IP за Caddy

В отсутствие `PULSE_TRUSTED_PROXY_CIDRS` приложение игнорирует клиентский
`X-Forwarded-For` и считает источником непосредственного TCP-peer.
Это исключает подмену IP заголовком, но за Caddy приводит к одному общему
rate-limit bucket: все внешние посетители могут блокировать друг друга.

До допуска в production необходимо:
1. Узнать точную подсеть, из которой Caddy подключается к ПУЛЬС.
2. Закрепить предсказуемый CIDR доверенной edge-сети или иной надёжный peer.
3. Настроить `PULSE_TRUSTED_PROXY_CIDRS` только для этой подсети.
4. Проверить, что reverse proxy самостоятельно формирует X-Forwarded-For,
   а внешние клиенты не могут подсунуть произвольный заголовок.
5. Пройти тест прямого соединения и тест spoofing.

Нельзя указывать `0.0.0.0/0` или доверять любым proxy headers.

## Операционный контроль

После смены `ADMIN_PASSWORD` потребуется отозвать действующие сессии
через отдельную административную команду, которую нужно добавить до RC.
На текущем этапе отзыв поддерживается при logout и по времени жизни.
