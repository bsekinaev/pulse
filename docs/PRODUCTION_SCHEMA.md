# PULSE-017: запуск production только после Alembic

В версии 0.2.0 приложение **не использует** `Base.metadata.create_all()`
в режиме `APP_ENV=production`. При запуске оно требует таблицу
`alembic_version` и совпадение единственной ревизии с текущим Alembic head.
Если схема не подготовлена, старт завершается с ошибкой, не изменяя БД.

В тестовом режиме сохранено `create_all()`, поэтому быстрые unit-тесты и
браузерный тест используют отдельные изолированные базы.

## Условный порядок будущего развёртывания (не выполнять сейчас)

1. Пройти read-only preflight VPS и сверить SHA релизного кандидата.
2. Проверить наличие свежей резервной копии SQLite за пределами Docker volume.
3. Восстановить копию на отдельном стенде.
4. Проверить `python -m scripts.migrate_sqlite` на восстановленной копии.
5. Сверить таблицы и счётчики до и после миграции.
6. Только после утверждения релиза повторить миграцию штатного volume в
   отдельном одноразовом контейнере образа v0.2.0 **до** запуска веб-сервера.
7. После успешной миграции обновить контейнер приложения и проверить health,
   авторизацию, анкету, проблемы, Caddy и основной сайт.
8. При сбое восстанавливать данные по согласованной отдельной процедуре.
   Откат только образа на 0.1.0 после миграции схемы не гарантирован.

**Важно:** демо ПУЛЬС уже опубликовано. Пункты выше пока лишь
документированная инструкция, никаких команд на production не запускали.
