# PULSE-018: репетиция миграции без production

Добавлен автоматический интеграционный сценарий:

1. Создание схемы **ровно из трёх таблиц v0.1.0**, без Alembic.
2. Заполнение полного синтетического набора: 8 сотрудников, 4 анкеты,
   3 обращения с одним закрытым.
3. Создание согласованной SQLite-копии через SQLite Backup API.
4. Восстановление копии в **новый файл**.
5. Применение `stamp_existing` + `upgrade head` только к восстановленной БД.
6. Побайтовое логическое сравнение **всех строк** бизнес-таблиц до и после
   миграции, включая тексты, статусы и даты.
7. Проверка появления таблиц авторизации и номера Alembic `20261111_0002`.
8. Запуск production FastAPI на восстановленной БД и контроль неизменности строк.

В тесте не используется действующий Docker volume и не выполняется
никаких операций на VPS.

**Следующий обязательный этап:** повторить репетицию уже на **копии
фактической SQLite с VPS** в изолированном окружении; до этого тест
доказывает совместимость лишь с синтетическим воспроизведением v0.1.0.


## Windows / Python 3.12: обязательные данные часовых поясов

При локальной репетиции реальной SQLite обнаружено, что Windows без
системной IANA-базы не может импортировать
`ZoneInfo("Europe/Minsk")` без пакета `tzdata`.
Зависимость `tzdata>=2025.2` добавлена в основные зависимости проекта
(не только в тестовое окружение); есть отдельный регрессионный тест.

После обновления исходников в том же виртуальном окружении повторить:

```powershell
& $python -m pip install -e ".[dev]"
& $python -m pytest -q tests/test_timezone_data.py tests/test_legacy_upgrade.py tests/test_migrations.py
```

Это не требует повторного снимка с VPS и не меняет production.
