# Безопасное развёртывание ПУЛЬС на VPS

Цель: `https://pulse.bsekinaev.ru` без воздействия на основной `bsekinaev.ru`.

## 1. Read-only preflight

Сначала проверьте:

```bash
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'
docker network ls
ss -lnt | grep -E ':(80|443|18120)\\b' || true
getent ahostsv4 pulse.bsekinaev.ru || true
```

Не меняйте работающие контейнеры основного сайта.

## 2. Подготовка каталога

На VPS в отдельном каталоге:

```bash
git clone https://github.com/bsekinaev/pulse.git
cd pulse
cp .env.example .env
chmod 600 .env
```

Замените секреты в `.env`. Для генерации используйте `python3 -c 'import secrets; print(secrets.token_urlsafe(48))'` (два разных случайных значения). Не публикуйте содержимое `.env` в чатах или логах.

```bash
docker compose config --quiet
docker compose up -d --build
docker compose ps
curl --fail --silent --show-error http://127.0.0.1:18120/health
```

При ошибке сначала проверьте `docker compose logs --tail=80 pulse`.

## 3. DNS и Caddy

Убедитесь, что DNS `pulse.bsekinaev.ru` указывает на VPS. Возможность редактировать DNS нужно проверить отдельно.

**Важное различие:**

- Если Caddy запущен **на хосте**, reverse proxy может использовать `127.0.0.1:18120`.
- Если Caddy запущен **в Docker**, адрес `127.0.0.1` внутри его контейнера не указывает на хост. Подключите контейнер ПУЛЬС и Caddy к общей выделенной Docker-сети и используйте `pulse-demo:8000` как upstream. Создавать общую сеть следует после проверки конфигурации существующих контейнеров.

Не выполняйте `docker compose down` в каталоге основного сайта. Не заменяйте Caddyfile целиком. Добавьте отдельный сайт-блок в используемый конфиг; до reload выполните Caddy validate.

Проверьте:

```bash
curl -I https://pulse.bsekinaev.ru/login
curl -I https://bsekinaev.ru/
```

Для страниц, не поддерживающих HEAD, используйте `curl -L -o /dev/null -w '%{http_code}\n' URL`.

## 4. Ручная приёмка

- Войти в панель.
- Открыть карточку Алексея.
- Отправить анкету с отрицательным ответом.
- Найти появившуюся проблему.
- Закрыть её с комментарием.
- Проверить изменение показателей.
- Проверить мобильную ширину 360 px.
- Проверить, что основной сайт доступен.

## 5. Откат

1. Удалите только добавленный сайт-блок `pulse.bsekinaev.ru`, проверьте конфигурацию, перезагрузите Caddy без пересоздания контейнера сайта.
2. В каталоге `pulse` выполните `docker compose down` **без `-v`**.
3. Убедитесь, что основной сайт и Caddy работают.
4. Сохраните том с SQLite до отдельного решения об удалении.

Если к сроку сдачи HTTPS недоступен, используйте предусмотренный заданием резерв: работающий локальный стенд и видео до трёх минут.
